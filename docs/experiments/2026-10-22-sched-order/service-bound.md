# 服务界限（在步骤 2/3 测量之前记录）

最低服务界限只适用于同一 iface 上持续**可发送**的 Peer。只有应用数据但 rwnd=0、cwnd/PRR=0、pacing 尚未到期或预算不足的 Peer，不能保证在指定出口字节数内发送。强行服务这些 Peer 正是步骤 1 要消除的白调度。

实现按已接受的完整 IP 包字节（含头部、重传与控制包）扣 deficit。每次新 visit 加固定 Q，服务到余额非正，末包产生的负债带到下次；Peer ready 队列变空则 deficit 清零。Q 与连接速率无关，有效值不小于 iface MTU / 最大 TSO 包，确保一次有效 visit 至少能发一包。Full 和 round cap 中断保持同一 visit 的剩余额度，恢复时不再增加 Q。

令 L 为该 iface 最大线上包长，则一次完整 visit 最多服务 `B=Q+L−1` 字节。P 个持续可发送 Peer 的两次服务之间，最多有 `(P−1)B` 字节的其他 Peer 出口流量（跨 iface 的流量、出口冻结的墙钟时间、对端 ACK 等待时间不计入这一局部保证）。若包长恰能整除 Q，界限退化为任务中的 `(P−1)Q`。

这不是对原要求严格 `(P−1)Q` 的证明：例如 Q=16384、L=1420 时，12 包为 17040 字节，会越过理想 quantum 656 字节。不能在保留完整报文和标准 deficit 借欠语义的同时声称这一误差为零。回归测试记录真实包序列并验证带报文取整的界限；报告保留理想界限的反例，不用改旧断言掩盖。

步骤 3 交替放行至多一个 new visit 和一个 ordinary visit；有 ordinary Peer 时，连续新 Peer 最多先消耗 B 字节。N 个持续可发送 ordinary Peer 的相邻服务间隔上界为 `(2N−1)B`，并非延迟对所有 Peer 同时变好。

判定：理想无报文误差的严格字节界限未满足，任何正向实验结果仍不能据此晋升开关。所有门禁与 1% 性能阈值继续使用最初冻结计划，未因看到结果而放宽。
